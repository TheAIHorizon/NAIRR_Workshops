# Workshop 2 — Train vs. Tune vs. RAG

A hands-on, side-by-side comparison of the **three ways to make an AI model useful for your topic** —
training from scratch, fine-tuning, and retrieval-augmented generation (RAG) — all on the **same base
model, the same knowledge, and the same test questions** so the differences are unmistakable.

> **Part of AI Horizon** (NSF #2528858, CSUSB Center for Cyber and AI).
> **Status: DRAFT** — the GPU build notebooks (01, 02) should be test-run on a GPU instance before class.

## The big idea

| Approach | What changes | Best for | Cost |
|----------|--------------|----------|------|
| **Train from scratch** | The model learns everything from your data, from zero | A brand-new capability (rarely worth it) | 💰💰💰 |
| **Fine-tune (LoRA)** | Adapts a pretrained model's behavior/format | New tone, style, or format | 💰 |
| **RAG** | Nothing — retrieves facts at question time | New / changing / private facts | ¢ |

**Decision rule:** new *facts* → RAG · new *behavior* → fine-tune · new *capability* → train.

## How the session runs

1. **Instructor builds live on a GPU** (e.g. Jetstream2 `g5.xl`): run **00 → 01 → 02 → 03**, discussing
   each approach. This produces an `artifacts/` folder (tiny trained model, LoRA adapter, RAG index).
2. **Instructor shares `artifacts/`** with students — via a Hugging Face repo (set `HF_REPO` in 00/02)
   or by zipping the folder. *(Model weights don't belong in GitHub — keep code here, weights on HF.)*
3. **Students run the comparison** (**04**) on a regular CPU instance — same base model, four setups,
   one set of questions. They see *which approach wins which kind of question, and why.*
