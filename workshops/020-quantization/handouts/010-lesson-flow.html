Quantization: Size vs. Speed vs. Quality

Run one model at four precisions and find the sweet spot between "small and fast" and "best answers."

The big idea

Quantization stores a model's numbers at lower precision. Lower precision means less disk, less memory, and faster generation — but past a point, answer quality drops. We run the same Qwen3 model at four levels and measure exactly where that trade-off lands.

Level~Size (1.7B)Role
Q4_K_M~1.1 GBSmallest / fastest — the popular default
Q6_K~1.5 GBA middle ground
Q8_0~1.8 GBNear-full quality
F16~3.4 GBFull precision — the reference
🧪

Why it's a fair test

Same model, same prompts, one precision at a time. We load each quant, benchmark it, then unload before the next — so the only thing changing is the precision.

Two switches in the config cell

What to look for

DimensionExpectation
Size & speedQ4 ≈ ⅓ of F16's size and noticeably faster
Everyday promptsAll precisions answer about the same
Hard prompts (reasoning, code, strict format)Where lower quants start to drift or break
Sweet spotUsually Q4_K_M / Q6_K — most of the quality, a fraction of the size
