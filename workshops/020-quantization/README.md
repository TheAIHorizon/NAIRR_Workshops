# Workshop 020 — Quantization: Size vs. Speed vs. Quality

Run the **same model (Qwen3) at four precisions** — Q4_K_M, Q6_K, Q8_0, and full F16 — and measure the
trade‑off on identical prompts. This is the deep dive into the "quantization changes quality" lesson
from the local‑LLM frameworks lab.

> **Part of AI Horizon** (NSF #2528858, CSUSB Center for Cyber and AI).
> **Status: DRAFT** — test‑run on an instance before class.

## The question
As you shrink a model from 16‑bit down to 4‑bit, **how much disk/RAM/speed do you save, and where (if
anywhere) does answer quality actually suffer?**

| Level | ~Size (1.7B) | Role |
|-------|--------------|------|
| Q4_K_M | ~1.1 GB | smallest/fastest — the popular default |
| Q6_K | ~1.5 GB | middle ground |
| Q8_0 | ~1.8 GB | near‑full quality |
| F16 | ~3.4 GB | full precision — the reference |

## Options (set in the config cell)
- **`MODEL_SIZE`** — `"1.7b"` (default; all four quants fit a 20 GB disk) or `"8b"` (realistic local
  size; the notebook **deletes each GGUF after testing** to reclaim disk).
- **`TEST_MODE`** — `"single"` / `"simple"` / `"complete"` (trade run time for coverage).
